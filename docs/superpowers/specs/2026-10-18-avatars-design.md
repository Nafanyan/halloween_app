# Аватары игроков и лавка только на экране — дизайн

Дата: 2026-10-18. Дополняет [дизайн квиза](2026-10-18-quiz-buzzer-design.md) и [дизайн лавки](2026-10-18-shop-design.md).

## Цель

1. **Лавка — только на большом экране.** Игроки выбирают предметы вслух, ведущий
   оформляет покупку в админке, анимация идёт на ТВ. На телефоне витрины нет;
   купленный предмет просто появляется в трофеях игрока.
2. **Аватары.** Игрок может поставить свою картинку. Её видно на ТВ (лобби,
   таблица очков, анимация покупки), в шапке его телефона и в админке.

**Критерии успеха**
- Пока лавка открыта, телефон показывает обычный экран: кнопку («Ждём вопрос…») и свёрнутые трофеи; витрины и мини-анимации покупки на телефоне нет.
- Игрок ставит аватар при входе (необязательно) или потом из шапки телефона, может сменить и убрать.
- Фото с камеры телефона (несколько МБ) загружается: телефон сам ужимает его до квадрата 256×256 JPEG.
- Без аватара везде показывается заглушка — первая буква ника в круглой рамке.
- Ведущий может убрать аватар у любого игрока.
- Аватары переживают перезапуск сервера; файл аватара удаляется при замене, снятии, удалении игрока и «Новой игре» с удалением игроков.

**Вне рамок**
- Ручное кадрирование (обрезка всегда по центру).
- Анимированные картинки, GIF.
- Модерация, кроме кнопки ведущего «убрать аватар».

## Принятые решения

| Вопрос | Решение |
|---|---|
| Где виден аватар | ТВ: лобби, таблица очков, анимация покупки. Телефон: шапка своего игрока. Админка: список игроков. |
| Когда ставится | При входе — необязательная кнопка «Выбрать фото» с превью; потом — нажатие на аватар в шапке → «Сменить фото» / «Убрать». |
| Как загружается | По сокету игрока событием `player:setAvatar` (бинарные данные). Игрок уже привязан к сокету — отдельной авторизации не нужно. |
| Обработка на телефоне | Центральная квадратная обрезка, 256×256, JPEG качества 0.85. |
| Проверка на сервере | Не больше 1 МБ; тип по сигнатуре байтов — JPEG, PNG или WebP. |
| Мини-анимация у покупателя | Убирается. Трофей появляется в списке после покупки. |

## Данные

`shared/src/types.ts`:
- `Player` получает необязательное поле `avatar?: string` — URL вида `/media/avatars/<uuid>.<ext>`.
- `PurchasedEvent` получает `playerAvatar?: string` — для анимации на ТВ.
- Новый `ErrorCode`: `INVALID_IMAGE`.

Поле `avatar` сохраняется в `state.json` вместе с игроком. Загрузка старого
`state.json` без поля работает как есть (поле необязательное).

## Сервер

**События** (`shared/src/events.ts`):
- `player:setAvatar`: `(p: { image: ArrayBuffer | null }, ack: (r: { ok: true } | { ok: false; error: ErrorCode }) => void)`. `null` — убрать аватар.
- `admin:clearAvatar`: `(p: { playerId: string }, ack)` — обычный ack админских команд.

**Чистая логика** — `server/src/game/avatar.ts`:
- `imageExt(buf: Uint8Array): 'jpg' | 'png' | 'webp' | null` — тип по сигнатуре.
- `setAvatar(s: GameState, playerId: string, url: string | undefined): Result` — `NOT_FOUND`, если игрока нет.

**Ввод-вывод** — в `server.ts`:
- `player:setAvatar`: сокет без привязанного игрока → `NOT_FOUND`; размер > 1 МБ или `imageExt` = null → `INVALID_IMAGE`. Иначе файл пишется в `<mediaDir>/avatars/<uuid>.<ext>`, затем `commit(setAvatar(...))`, затем удаляется старый файл игрока (если был).
- `admin:clearAvatar`: снять поле, удалить файл.
- `admin:removePlayer` и «Новая игра» с удалением игроков удаляют файлы аватаров удалённых игроков.
- Удаление файла — только внутри `<mediaDir>/avatars/`, по имени из URL; ошибки удаления (файла нет) игнорируются.
- `maxHttpBufferSize` Socket.IO — 2 МБ, чтобы картинка до 1 МБ доходила до проверки и получала понятную ошибку.
- `admin:sell` кладёт `playerAvatar` в `shop:purchased`.

**Проекции** (`views.ts`): `avatar` есть у игроков в публичном и админском виде.

`.gitignore`: `server/data/media/avatars/`.

## Клиент

**Общее:**
- `client/src/avatar/crop.ts` — `squareCrop(w, h): { sx, sy, size }` (чистая, под тест) и `avatarBlob(file: File): Promise<Blob>` (canvas → JPEG 256×256).
- `client/src/avatar/Avatar.tsx` — `<Avatar name avatar size />`: круг с картинкой или первой буквой ника (заглавной), рамка в стиле игры.

**Телефон** (`PlayerPage.tsx`):
- Экран входа: под полем ника кнопка «Выбрать фото» (`<input type="file" accept="image/*">`), после выбора — превью и «убрать». После успешного входа фото отправляется; если загрузка не удалась — вход остаётся, показывается «Не удалось загрузить фото».
- Шапка: `<Avatar>` слева от ника. Нажатие открывает маленькое меню «Сменить фото» / «Убрать» (второй пункт только при наличии аватара).
- Убираются `Showcase` и `PurchaseReveal` с телефона; условие `shopOpen` больше не меняет экран. `Trophies` всегда свёрнутые, `hideIds` из очереди покупок больше не нужен на телефоне — трофей появляется сразу.

**ТВ:** `<Avatar>` рядом с ником в `Lobby` и `Scoreboard`; в `PurchaseReveal` — рядом со строкой «такой-то получил…». Длинные ники продолжают переноситься по прежним правилам.

**Админка** (`PlayersPanel.tsx`): маленький `<Avatar>` у каждого игрока и кнопка «убрать аватар» (видна, когда аватар есть).

## Ошибки

| Ситуация | Что видит игрок |
|---|---|
| Файл не декодируется браузером | «Не удалось загрузить фото» |
| Сервер ответил `INVALID_IMAGE` | «Не удалось загрузить фото» |
| Нет соединения | Сокет сам переподключится; повторить вручную |

## Тесты

- `server/test/avatar.test.ts`: `imageExt` для JPEG/PNG/WebP и мусора; `setAvatar` ставит, заменяет, снимает, `NOT_FOUND`.
- `server/test/server.test.ts` (интеграционно, как существующие тесты сокетов): загрузка пишет файл и меняет `avatar` в виде; замена удаляет старый файл; > 1 МБ и не-картинка → `INVALID_IMAGE`; `admin:clearAvatar` и удаление игрока удаляют файл; `shop:purchased` несёт `playerAvatar`.
- `client/test/crop.test.ts`: `squareCrop` для горизонтального, вертикального и квадратного изображения.
- Ручная проверка на тестовом порту (не 3000): вход с фото с телефона, смена, удаление, вид на ТВ и в админке, открытая лавка не меняет экран телефона.
