# Библиотека игр — дизайн

Дата: 2026-10-19. Часть 1 из 4 большой доработки «конструктор игр»:

1. **Библиотека игр** (этот документ) — несколько игр-шаблонов со своими настройками, вопросами и магазином.
2. Редактор вопросов в админке с загрузкой картинок и аудио.
3. Новые типы вопросов (соответствие, пропуски, варианты и т. п.) — показываются на ТВ, отвечают вслух, судит ведущий.
4. Звуки интерфейса.

## Цель

Ведущий в админке создаёт отдельные игры: у каждой свои тексты лобби, музыка
лобби, фон, правила очков, раунды/темы/вопросы и каталог магазина. Игры
хранятся на диске и переживают перезапуск сервера. В каждый момент активна
одна игра; её и играют.

**Критерии успеха**
- Новую игру можно создать, наполнить магазином и настройками, не трогая файлы руками.
- Игра — переносимая папка: скопировал `games/<id>` на другой компьютер — игра есть.
- Текущая игра «Сумеречный шабаш» после обновления работает как раньше: вопросы, предметы, игроки, очки и покупки на месте.
- Битый `game.json` не роняет сервер.

**Вне рамок (части 2–4)**
- Визуальный редактор вопросов: до части 2 вопросы новой игры правятся в её `game.json` руками.
- Новые типы вопросов, звуки интерфейса.
- Сохранение прогресса отдельно для каждой игры.
- Свои цвета/шрифты для игры (меняется только фоновое изображение).

## Принятые решения

| Вопрос | Решение |
|---|---|
| Что такое игра | Шаблон: настройки + вопросы + каталог магазина |
| Прогресс (игроки, очки, клетки, покупки) | Один общий; смена активной игры его сбрасывает (игроки остаются) |
| Настраиваемое | Название, подзаголовок лобби, описание (для админки), музыка лобби, фон, штраф за неверный ответ, стартовые очки |
| Хранение | Папка на игру: `server/data/games/<id>/game.json` + `media/` |
| Старая игра | Автоматическая миграция в первую игру при первом запуске |

## Данные

### На диске

```
server/data/
  state.json                 прогресс вечера + activeGameId
  media/avatars/…            аватарки игроков (общие, без изменений)
  questions.json             после миграции не читается, остаётся как резервная копия
  games/<id>/game.json       шаблон игры
  games/<id>/media/…         картинки и музыка этой игры (без подпапок)
```

`<id>` — `g-` + 8 символов `[a-z0-9]`, совпадает с именем папки и проверяется
регуляркой `^g-[a-z0-9]{8}$` везде, где приходит от клиента.

### `game.json`

```json
{
  "version": 1,
  "title": "Сумеречный шабаш",
  "subtitle": "Наведи телефон на знак — и входи в лес",
  "description": "",
  "lobbyMusic": "dark-forest.mp3",
  "background": "3f2a….jpg",
  "scoring": { "wrongPenalty": false, "startScore": 0 },
  "rounds": [ { "name": "…", "themes": [ { "name": "…", "questions": [ { "value": 100, "text": "…", "answer": "…", "image": "izbushka.svg" } ] } ] } ],
  "shop": [ { "id": "…", "name": "…", "description": "…", "price": 100, "quantity": 1, "hidden": false, "image": "a1b2….jpg" } ]
}
```

- `title`: 1–60 символов; `subtitle`: 0–120; `description`: 0–500.
- `lobbyMusic`, `background`, `question.image/audio`, `shop[].image` — необязательные имена файлов в `games/<id>/media/`; файл обязан существовать. Без `background` используется встроенный гобелен.
- `scoring.wrongPenalty` (boolean): при `true` неверный ответ снимает номинал вопроса. `scoring.startScore`: целое 0–100000, начисляется игроку при входе и при сбросе прогресса.
- `rounds` может быть пустым массивом (пустая игра); темы и вопросы внутри раунда — по текущим правилам `questions.ts`.
- Медиа раздаются по `/games/<id>/media/<файл>`. Клиент получает уже готовые URL.

### Типы (`shared/src/types.ts`)

- `GameSettings { title; subtitle; description; lobbyMusic?; background?; scoring: { wrongPenalty; startScore } }`.
- `GameDef extends GameSettings { version: 1; rounds: Round[]; shop: ShopItem[] }`.
- `GameSummary { id; title; description; rounds; questions; active: boolean; error?: string }` — для списка в админке.
- `GameState`: добавляется `activeGameId: string`; `shop` становится `{ open; purchases }` (каталог уезжает в игру).
- `PublicView` получает `game: { title; subtitle; background?: string; lobbyMusic?: string }` (URL).
- `AdminView` получает `games: GameSummary[]` и `editing: { id; settings: GameSettings; shop: AdminShopItem[] } | null` — игра, открытая в редакторе (у каждого админ-сокета своя).
- Новые `ErrorCode`: `NO_QUESTIONS`, `GAME_BROKEN`, `GAME_ACTIVE`, `INVALID_SETTINGS`.

## Сервер

### Модули

- `server/src/games/store.ts` — чтение/запись папок игр: `listGames`, `loadGame(id)` → `GameDef | { error }`, `saveGame(id, def)` (атомарно: tmp + rename), `createGame`, `duplicateGame` (копия папки, новый id, к названию « (копия)»), `deleteGame` (рекурсивно удаляет папку), `sweepMedia(id, def)` (удаляет файлы `media/`, на которые нет ссылок).
- `server/src/games/validate.ts` — валидация `game.json`; переиспользует проверки из `questions.ts` (раунды/темы/вопросы) и `parseItem` из `shop.ts` (с новым форматом `image` — имя файла). Ошибки — с путём поля, как сейчас.
- `server/src/games/migrate.ts` — разовая миграция.
- `server/src/games/upload.ts` — определение типа по сигнатуре байтов.
- `questions.ts` сохраняет функции поиска вопроса и валидации раундов; `loadQuestions` остаётся только для миграции.

### Миграция (при старте, если нет `games/`)

1. Создать игру `Сумеречный шабаш` с текущим подзаголовком лобби.
2. Скопировать `questions.json` → `rounds`, файлы из `media/` (кроме `avatars/` и `shop/`), на которые ссылаются вопросы, → `games/<id>/media/`.
3. Перенести `state.shop.items` в `shop`, их файлы из `media/shop/` скопировать в `games/<id>/media/`, ссылки переписать на имя файла.
4. Записать `activeGameId` в `state.json`; покупки и очки сохраняются.
5. Старые файлы не удаляются. Если `questions.json` отсутствует или битый — создаётся пустая игра «Новая игра».

### Старт без миграции

Загружаются все игры. Битые остаются в списке с текстом ошибки. Если активная
игра отсутствует или битая — активной становится первая исправная по названию
(прогресс сбрасывается, игроки остаются); если исправных нет — создаётся пустая.
Затем для каждой исправной игры выполняется `sweepMedia`.

### События сокета (только админ)

| Событие | Действие |
|---|---|
| `game:create {title}` | Пустая игра; ack `{ ok, id }` |
| `game:duplicate {id}` | Копия папки; ack `{ ok, id }` |
| `game:delete {id}` | Нельзя для активной (`GAME_ACTIVE`) |
| `game:activate {id}` | Нельзя для битой (`GAME_BROKEN`). Сброс как `newGame` с сохранением игроков: очки = `startScore`, клетки/покупки очищены, лавка закрыта, фаза lobby |
| `game:open {id}` | Делает игру редактируемой для этого сокета (`editing` в `AdminView`); `id: null` — закрыть |
| `game:updateSettings {id, settings}` | Валидация (`INVALID_SETTINGS`), запись |
| `admin:itemAdd/itemUpdate/itemDelete` | Получают `gameId`; правят каталог этой игры. Удаление предмета активной игры удаляет и его покупки (как сейчас) |

`admin:shopOpen`, `admin:sell`, `admin:cancelPurchase` работают с активной игрой.
`admin:startGame` возвращает `NO_QUESTIONS`, если в активной игре нет вопросов.
`admin:wrong` при `wrongPenalty` вычитает номинал (очки могут уйти в минус).
`player:join` выдаёт `startScore`.

После любого изменения игры рассылаются `state:public` (если изменилась активная)
и `state:admin` всем админам.

### Загрузка медиа

`POST /api/games/:id/media`, заголовок `X-Admin-Pin`, тело — сырые байты.

- Картинки: jpg, png, webp, svg — до 5 МБ. Аудио: mp3, ogg, wav, m4a — до 20 МБ.
- Тип определяется по сигнатуре содержимого (для svg — начало текста `<svg` или `<?xml`), а не по заголовку. Неизвестное — 415, слишком большое — 413, нет игры — 404, неверный PIN — 401.
- Имя файла — `<uuid>.<ext>`; ответ `{ file, url }`.
- Старый `/api/shop/image` удаляется; клиент магазина переходит на новый эндпоинт.

## Интерфейс

### Админка

- Сверху две вкладки: **«Ведущий»** (нынешний экран: лобби/сетка/вопрос, игроки, открытие лавки и продажа) и **«Игры»**.
- **«Игры»**: карточки — название, описание, «N раундов · M вопросов», метка «Активна», для битой — текст ошибки красным. Кнопки: «Открыть», «Дублировать», «Удалить» (с подтверждением; недоступна для активной), «Сделать активной» (подтверждение: «Очки и покупки сбросятся, игроки останутся»). Внизу «+ Новая игра» (спрашивает название).
- **Страница игры** (после «Открыть»), три раздела:
  - **Настройки** — название, подзаголовок, описание; фон (загрузка, превью, «Убрать»); музыка лобби (загрузка, плеер для прослушивания, «Убрать»); «Снимать очки за неверный ответ»; «Стартовые очки». Кнопка «Сохранить».
  - **Магазин** — нынешний редактор предметов (`ItemForm`/список), привязанный к этой игре.
  - **Вопросы** — сводка по раундам и подсказка: «Редактор вопросов появится позже; пока вопросы правятся в `server/data/games/<id>/game.json`».

### ТВ

- Лобби: название и подзаголовок из игры; фон — из игры (CSS-переменная поверх темы), иначе гобелен.
- Музыка лобби играет по кругу, тихо (громкость 0.4), плавно затихает за 1.5 с при выходе из лобби.
- Если браузер запретил автовоспроизведение, в углу показывается плашка «🔊 Нажмите, чтобы включить звук»; первый клик снимает блокировку (пригодится части 4).

## Обработка ошибок

- Ошибка в `game.json` → игра в списке как битая с адресом поля; сервер работает.
- Ошибка записи на диск → ack `{ ok: false }` с тостом «Не удалось сохранить»; состояние в памяти не меняется.
- Отказ загрузки → тост с причиной (большой файл / неподдерживаемый тип).

## Тестирование

- Юнит: `validate.ts` (корректные/битые поля, пустые раунды, отсутствующий файл), `upload.ts` (сигнатуры всех форматов, мусор), `store.ts` во временной папке (create/duplicate/delete/save атомарно/sweepMedia), `migrate.ts` (полная, без `questions.json`, с предметами и покупками).
- Логика: штраф за неверный ответ, стартовые очки при входе и сбросе, `activate`, `NO_QUESTIONS`.
- Сервер (socket.io + HTTP): события `game:*`, права админа, загрузка (401/404/413/415/200), старт с битой активной игрой.
- Ручная проверка в браузере: вкладки админки, создание игры с фоном и музыкой, активация, лобби на ТВ, плашка звука.
