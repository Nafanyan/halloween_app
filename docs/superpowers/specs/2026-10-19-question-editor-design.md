# Редактор вопросов — дизайн

Дата: 2026-10-19. Часть 2 из 4 доработки «конструктор игр». Опирается на
[библиотеку игр](2026-10-19-games-library-design.md) (часть 1, готова).

## Цель

В редакторе игры (вкладка «Игры» → «Открыть») раздел «Вопросы» становится
полноценным конструктором: раунды, темы и вопросы создаются, переименовываются,
переставляются и удаляются прямо в админке; у вопроса задаются номинал, текст,
ответ, картинка и музыка. Править `game.json` руками больше не нужно.

**Критерии успеха**
- Ведущий собирает раунд «тема + 3 вопроса с картинкой и музыкой» без файлов и перезапусков.
- Опечатку в ответе неактивной игры или активной в лобби можно исправить за пару кликов.
- Во время игры структура активной игры не может «поехать»: правки отклоняются.
- Новые типы вопросов (часть 3) встраиваются в форму вопроса без переделки редактора.

**Вне рамок**
- Новые типы вопросов (соответствие, пропуски и т. п.) — часть 3.
- Звуки интерфейса — часть 4.
- Совместное редактирование: при одновременных правках двух админов сохраняется последняя.
- Перетаскивание мышью (перестановка — кнопками ↑ ↓).
- Перенос вопроса между темами/раундами.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Правка активной игры во время игры | Нельзя: раздел «Вопросы» только для чтения, сервер отвечает `GAME_LOCKED`. В лобби и у неактивных игр — можно всё |
| Как сохраняется | Клиент присылает весь массив `rounds` одним событием; сервер валидирует и пишет `game.json` |
| Когда сохраняется | Перестановка, удаление, добавление, переименование — сразу; форма вопроса — по кнопке «Сохранить» |
| Черновики | Раунд без тем и тема без вопросов допустимы |

## Данные

Формат `game.json` не меняется (`rounds[].themes[].questions[]`, вопрос —
`{ value, text, answer, image?, audio? }`).

Правила валидации раундов (в `game.json` и в событии редактора — одни и те же):

- `rounds` — массив, может быть пустым; `round.themes` — массив, может быть пустым; `theme.questions` — массив, может быть пустым.
- `round.name`, `theme.name` — 1–60 символов после trim.
- `question.value` — целое 1–100000.
- `question.text` — 1–1000 символов после trim; `question.answer` — 1–500.
- `question.image` — имя файла в `games/<id>/media/` с расширением jpg/png/webp/svg; `question.audio` — mp3/ogg/wav/m4a. Файл обязан существовать.
- Ошибки — с путём поля, как сейчас (`rounds[0].themes[1].questions[2].answer: …`).

Миграция старого `questions.json` (часть 1) продолжает требовать непустой список раундов.

### Типы (`shared/src/types.ts`)

- `GameEditView.rounds` меняется на полные данные: `EditRound[]`, где
  `EditRound { name: string; themes: EditTheme[] }`,
  `EditTheme { name: string; questions: EditQuestion[] }`,
  `EditQuestion extends Question { imageUrl?: string; audioUrl?: string }` (`image`/`audio` — имена файлов, `*Url` — URL для превью).
- `GameEditView` получает `locked: boolean` — `true`, если игра активна и фаза `game`.
- Новый `ErrorCode`: `GAME_LOCKED`; `INVALID_QUESTIONS` — ошибка валидации раундов.

## Сервер

### Событие

`game:updateRounds { id: string; rounds: Round[] }` → `Ack` (только админ).

1. `id` — по `GAME_ID_RE` и существует в библиотеке, игра исправна (иначе `NOT_FOUND` / `GAME_BROKEN`).
2. Игра активна и `state.phase === 'game'` → `GAME_LOCKED`.
3. `rounds` валидируются по правилам выше (`INVALID_QUESTIONS` при ошибке; текст ошибки пишется в лог сервера).
4. Сохранение `{ ...def, rounds }` через `lib.save`; ошибка записи → `SAVE_FAILED`.
5. Рассылка: `state:admin` всем админам; `state:public`, если игра активна.

### Публичный вид

- Темы без вопросов не попадают в сетку ТВ (`toPublicView`), id клеток по-прежнему считаются по исходным индексам.
- `roundNames` — все раунды, включая пустые.
- `startGame` — как в части 1: `NO_QUESTIONS`, если вопросов нет вовсе.

## Интерфейс (админка, раздел «Вопросы» в `GameEditor`)

- Плашка при `locked`: «Игра идёт — вопросы можно менять в лобби или после «Новой игры»». Все кнопки и поля раздела неактивны.
- **Раунд**: поле названия (сохраняется по потере фокуса / Enter, если изменилось), кнопки ↑ ↓ «Удалить раунд» (подтверждение `Удалить раунд «…» со всеми темами и вопросами?`). Внутри — темы, внизу «+ Тема».
- **Тема**: поле названия, ↑ ↓ «Удалить тему» (подтверждение `Удалить тему «…» со всеми вопросами?`). Внутри — список вопросов, внизу «+ Вопрос».
- **Строка вопроса**: `<номинал> · <первые 60 символов текста>` и значки 🖼 / 🎵 при наличии медиа; кнопки ↑ ↓ «Изменить» «Удалить» (подтверждение `Удалить вопрос на <номинал>?`).
- **Форма вопроса** (раскрывается на месте строки; новый вопрос открывается сразу в форме):
  - «Тип: Обычный» — пока единственный вариант (выпадающий список, место для части 3);
  - номинал (число), текст (textarea), ответ;
  - картинка и музыка — компонент `MediaField` из части 1 (загрузка, превью/плеер, «Убрать»);
  - «Сохранить» / «Отмена». Новый вопрос, отменённый до сохранения, не создаётся.
- Значения по умолчанию: новый раунд — `Раунд N`; новая тема — `Новая тема`; новый вопрос — номинал на 100 больше последнего в теме (первый — 100).
- Внизу раздела «+ Раунд».
- Каждое действие отправляет весь `rounds` событием `game:updateRounds`; при ошибке — тост, локальное состояние откатывается к последнему пришедшему с сервера.
- Подсказка «правьте game.json руками» удаляется из редактора и из README (в README раздел «Игры» описывает редактор; ручная правка остаётся как продвинутый вариант с прежним предупреждением).

### Компоненты

- `client/src/admin/questions/QuestionsPanel.tsx` — раздел целиком, держит локальную копию `rounds`, отправляет изменения.
- `client/src/admin/questions/RoundBlock.tsx`, `ThemeBlock.tsx`, `QuestionRow.tsx`, `QuestionForm.tsx`.
- `client/src/admin/questions/edit.ts` — чистые функции над `Round[]`: `addRound`, `renameRound`, `moveRound`, `removeRound`, `addTheme`, `renameTheme`, `moveTheme`, `removeTheme`, `addQuestion`, `updateQuestion`, `moveQuestion`, `removeQuestion`, `nextValue` (без мутаций, покрыты юнит-тестами).

## Ошибки

- `GAME_LOCKED` → тост «Игра идёт — вопросы можно менять в лобби».
- `INVALID_QUESTIONS` → тост «Проверьте поля вопроса».
- `SAVE_FAILED`, `NOT_FOUND`, `GAME_BROKEN` — существующие тосты.

## Тестирование

- Сервер: валидация (пустые темы/раунды допустимы, лимиты, тип медиа по расширению, отсутствующий файл), `game:updateRounds` (права, `GAME_LOCKED` в фазе игры и разрешение в лобби, сохранение на диск, `state:public` для активной, `SAVE_FAILED`), публичный вид без пустых тем.
- Клиент: юнит-тесты `edit.ts` (каждая операция, границы ↑ ↓, `nextValue`).
- Ручная проверка в браузере: собрать игру из раунда, двух тем и вопросов с картинкой и музыкой; переставить и удалить; начать игру и открыть вопрос на ТВ; убедиться, что редактор стал только для чтения; после «Новой игры» правки снова доступны.
