# Квиз «Сумеречный шабаш» — дизайн

Дата: 2026-10-18

## Цель

Локальное веб-приложение для квиза на домашней вечеринке. Сервер запускается на Mac
хозяина в домашней Wi-Fi сети. Гости подключаются к Wi-Fi, открывают ссылку
(или сканируют QR-код) на телефоне, регистрируются по имени и используют телефон
как кнопку «знаю ответ». Вопросы показываются на отдельном большом экране
(телевизор/ноутбук). Админ ведёт игру со своей панели.

Механика — в духе «Своей игры»: сетка «тема × стоимость», первый нажавший отвечает.

**Критерии успеха**
- Гости подключаются с телефонов без установки и аккаунтов.
- Ровно один игрок получает право ответа на каждое нажатие; блокировка мгновенно видна на всех экранах.
- Обрыв Wi-Fi, перезагрузка страницы или перезапуск сервера не теряют игроков и очки.
- Работает полностью без интернета.

**Вне рамок (пока)**
- Таймеры (темп держит админ).
- Штрафы за неверный ответ.
- Мини-игры и другие механики — архитектура должна позволять их добавить, но они не проектируются сейчас.

## Стек

- TypeScript везде.
- `server/` — Node.js + Express + Socket.IO.
- `client/` — React + Vite, одно приложение с тремя маршрутами.
- `shared/` — общие типы состояния и событий Socket.IO.
- Тесты — Vitest.
- Монорепозиторий на npm workspaces.

## Архитектура

Сервер — единственный источник истины. Клиенты отправляют **намерения**
(«нажал кнопку», «админ: верно»), сервер их валидирует, меняет состояние и
рассылает актуальное состояние всем клиентам. Клиенты сами ничего не решают.

Игровая логика — чистый модуль без сети и ввода-вывода
(`server/src/game/`): функции вида `(state, action) → newState | error`.
Слой Socket.IO только принимает события, вызывает логику, сохраняет и рассылает
результат. Это делает логику тестируемой и упрощает добавление новых механик.

Разные клиенты получают разные проекции состояния: правильный ответ на вопрос
отправляется **только** в админку.

## Экраны

### Игрок — `/`
- Первый вход: поле «Имя» и кнопка «Войти». Имя должно быть уникальным
  (без учёта регистра и пробелов по краям); при конфликте — «Это имя уже занято».
- После входа: своё имя, свои очки и большая кнопка. Состояния кнопки:
  - **неактивна** — нет открытого вопроса;
  - **активна** — вопрос открыт, можно жать;
  - **отвечает другой** — показывается имя отвечающего;
  - **ты отвечаешь** — подсветка;
  - **ты уже ошибся** — на этот вопрос жать нельзя.

### Большой экран — `/screen`
- При открытии — кнопка «Начать шабаш» (нужна, чтобы браузер разрешил звук).
- Режим «Лобби» (фаза `lobby`, до старта игры): крупный QR-код и текстовый адрес
  для подключения, список уже вошедших игроков (обновляется в реальном времени).
  Показывается, пока админ не нажмёт «Начать игру».
- Режим «Сетка» (фаза `game`): сетка текущего раунда (темы × стоимости, сыгранные клетки погашены),
  таблица очков (отключённые игроки серым). QR-кода нет.
- Режим «Вопрос»: тема, стоимость, текст, картинка (если есть), аудио (если есть).
  После нажатия — крупно имя отвечающего. Правильный ответ не показывается.

### Админ — `/admin`
- Вход по PIN (задаётся в конфиге сервера / переменной окружения, по умолчанию выводится в консоль при старте).
- В фазе `lobby`: список вошедших игроков и кнопка «Начать игру» → фаза `game`,
  большой экран переключается с QR-кода на сетку. Открывать вопросы можно только в фазе `game`.
- Сетка текущего раунда, клик по клетке открывает вопрос. Переключение раундов.
- Во время вопроса: текст и **правильный ответ**, кто отвечает, кто уже ошибся.
  Кнопки:
  - «Верно» — отвечающему +стоимость, вопрос закрыт;
  - «Неверно» — очки не меняются, кнопки снова открыты для всех, кроме ошибившихся;
  - «Частично» + поле числа — отвечающему +N, вопрос закрыт;
  - «Закрыть без ответа» — вопрос закрыт, очки не меняются;
  - управление аудио на большом экране: play / pause / сначала.
- Список игроков: очки, онлайн/офлайн, ручная правка очков (+/− произвольное число),
  удаление игрока.
- «Новая игра» с подтверждением: сбрасывает очки и сыгранные клетки
  (с опцией удалить и игроков) и возвращает фазу `lobby` (снова QR-код на экране).

Регистрация игроков открыта в любой фазе: опоздавший может войти по ссылке
и после старта игры.

## Игровой цикл

0. Фаза `lobby`: гости сканируют QR-код на большом экране и входят. Админ жмёт
   «Начать игру» → фаза `game`.
1. Админ выбирает несыгранную клетку → вопрос открывается на большом экране,
   кнопки игроков **сразу активны**.
2. Первое принятое сервером нажатие назначает отвечающего; кнопки у остальных блокируются.
3. Админ решает:
   - Верно → +стоимость, клетка сыграна, возврат к сетке.
   - Частично(N) → +N, клетка сыграна, возврат к сетке.
   - Неверно → игрок попадает в список ошибившихся, отвечающий сброшен,
     кнопки снова активны для остальных.
4. Админ в любой момент может закрыть вопрос без ответа → клетка сыграна.

Одновременно открыт максимум один вопрос. Пока кто-то отвечает, новые нажатия игнорируются.

## Формат вопросов

`server/data/questions.json`, медиафайлы — в `server/data/media/`.

```json
{
  "rounds": [
    {
      "name": "Раунд 1",
      "themes": [
        {
          "name": "Нечисть",
          "questions": [
            { "value": 100, "text": "Кто живёт в избушке на курьих ножках?", "answer": "Баба Яга" },
            { "value": 200, "text": "Угадай мелодию", "audio": "song1.mp3", "answer": "…" },
            { "value": 300, "text": "Кто на картинке?", "image": "leshy.jpg", "answer": "Леший" }
          ]
        }
      ]
    }
  ]
}
```

- `value`, `text`, `answer` — обязательны; `image`, `audio` — необязательны (имя файла в `media/`).
- Идентификатор вопроса — его позиция: `раунд/тема/вопрос`.
- Файл валидируется при старте сервера; при ошибке сервер не стартует и
  пишет понятное сообщение (путь к полю и что не так), включая отсутствующие медиафайлы.
- Медиа отдаётся сервером статически по `/media/<file>`.

## Состояние и хранение

Состояние (в памяти сервера):
- `phase`: `lobby | game`;
- `players`: `id`, `name`, `score`, `online`;
- `playedCells`: множество идентификаторов вопросов;
- `currentRound`;
- `activeQuestion`: id вопроса, `answeringPlayerId | null`, `wrongPlayerIds`.

После каждого изменения состояние атомарно (запись во временный файл + rename)
сохраняется в `server/data/state.json`. При старте сервер загружает его, если он есть;
`online` всех игроков сбрасывается в false. Если сохранённое состояние ссылается
на вопросы, которых больше нет в `questions.json`, эти ссылки отбрасываются.

## Подключение и сбои

- При регистрации телефон получает `playerId` и хранит его в `localStorage`.
  При переподключении отправляет его и восстанавливается с тем же именем и очками.
  Неизвестный `playerId` → снова форма имени.
- Socket.IO переподключается автоматически; отключённый игрок не удаляется, а помечается офлайн.
- Одному игроку могут соответствовать несколько вкладок; игрок онлайн, пока есть хотя бы одно соединение.
- Нажатия от игрока без права (нет вопроса, уже кто-то отвечает, игрок уже ошибся,
  повторное нажатие) молча игнорируются.
- Если отвечающий отключился, админ всё равно может нажать любую кнопку решения.
- Удаление игрока, который сейчас отвечает, работает как «Неверно» без внесения в ошибившиеся.
- Админ-события без успешной авторизации по PIN отклоняются.

## Запуск

- `npm start` — сборка клиента и запуск сервера на порту 3000 (переопределяется `PORT`).
  В консоли — LAN-адрес вида `http://192.168.x.x:3000` и PIN админа.
  Тот же адрес зашит в QR-код на большом экране в фазе лобби.
- `npm run dev` — сервер и Vite с горячей перезагрузкой.

## Тестирование

- Юнит-тесты игровой логики (Vitest): регистрация и уникальность имён, переход
  лобби → игра (вопрос нельзя открыть в лобби), открытие вопроса,
  первое нажатие, игнорирование лишних нажатий, верно / неверно / частично / закрыть,
  правка очков, удаление игрока, новая игра, сыгранные клетки.
- Валидация `questions.json`: корректный файл, отсутствующие поля, несуществующий медиафайл.
- Интеграционный тест: сервер + несколько клиентов Socket.IO одновременно жмут кнопку —
  отвечающий ровно один, все клиенты получают одинаковое состояние.
- Ручная проверка на реальных телефонах в сети перед вечеринкой.

## Оформление

В стиле приглашения «Сумеречный шабаш» (страшные русские сказки): тёмный фон,
золото, сказочный шрифт. Конкретика — при реализации. Интерфейс игрока
рассчитан на телефон (одна рука, крупная кнопка); большой экран — на 16:9 и
чтение с расстояния.
