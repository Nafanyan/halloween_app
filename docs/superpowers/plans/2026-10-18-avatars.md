# Аватары и лавка только на экране — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** игроки ставят свои аватары (видны на ТВ, в шапке телефона, в админке); лавка и анимация покупки уходят с телефонов.

**Architecture:** поле `avatar?: string` у `Player`; картинка приходит бинарником по сокету игрока (`player:setAvatar`), сервер проверяет сигнатуру и размер, пишет файл в `<mediaDir>/avatars/` и коммитит состояние чистой функцией `setAvatar`. Телефон сам режет фото в квадрат 256×256 JPEG. Общий компонент `<Avatar>` рисует картинку или первую букву ника.

**Tech Stack:** TypeScript strict, ESM, npm workspaces (shared/server/client), Express + Socket.IO, React 18 + Vite, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-18-avatars-design.md`

## Global Constraints

- Сервер на порту 3000 не запускать и не трогать. Тестовый сервер — только на другом порту (например 3100), после проверки остановить.
- Размер картинки на сервере — не больше 1 МБ (1 048 576 байт); типы по сигнатуре — JPEG, PNG, WebP.
- `maxHttpBufferSize` Socket.IO — 2 МБ (2 * 1024 * 1024).
- Телефон: центральная квадратная обрезка, 256×256, JPEG качества 0.85.
- Файлы аватаров: `<mediaDir>/avatars/<uuid>.<ext>`, URL `/media/avatars/<uuid>.<ext>`; удаление — только внутри `<mediaDir>/avatars/`, по `path.basename` из URL, ошибки удаления игнорируются.
- Тексты интерфейса: «Выбрать фото», «Сменить фото», «Убрать», «Не удалось загрузить фото», «убрать аватар».
- Без аватара — заглавная первая буква ника (по `[...name][0]`, чтобы не резать суррогатные пары) в круглой рамке.
- Тесты: `npm test` из корня; типы: `npx tsc --noEmit -p server` и `npx tsc --noEmit -p client`.

## Review Focus

1. **Сокет без игрока или игрок удалён между выбором и отправкой** → `NOT_FOUND`, файл на диск не пишется. Тест в задаче 2.
2. **`image` пришёл не бинарником** (строка, объект, число) → `INVALID_IMAGE`, сервер не падает. Тест в задаче 2.
3. **«Новая игра» без удаления игроков** сохраняет аватары и файлы; с удалением — файлы стираются. Тест в задаче 2.
4. **Файл аватара пропал с диска** (state.json пережил чистку media) → на клиенте `<img>` падает в `onError` и показывается буква. Проверяется в ручной проверке (задача 5) — вручную удалить файл.
5. **Загрузка после входа не удалась** (сервер ответил `INVALID_IMAGE` или фото не декодируется) → игрок остаётся вошедшим и видит «Не удалось загрузить фото». Ответ сервера покрыт тестом задачи 2; поведение `PlayerPage` проверяет ревьюер задачи 4 и ручная проверка (выбрать не-картинку, например .txt через «Файлы»).
